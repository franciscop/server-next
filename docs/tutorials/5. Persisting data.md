# Persisting data

The [REST API tutorial](/tutorials/1-build-a-rest-api) kept notes in a `Map`, so they vanish on restart. Swap it for a store built with the exported [`kv`](https://polystore.dev/) and the same code persists to Redis, the filesystem, DynamoDB, and more.

## 1. From Map to store

Server.js builds stores with [polystore](https://polystore.dev/), exported as `kv`. Back it with a `Map` in development:

```js
import server, { kv, status } from '@server/next';

const notes = kv(new Map());

export default server()
  .get('/notes', async () => {
    const ids = await notes.keys();
    return Promise.all(ids.map((id) => notes.get(id)));
  })
  .post('/notes', async (ctx) => {
    const id = crypto.randomUUID();
    const note = { id, text: ctx.body.text };
    await notes.set(id, note);
    return status(201).json(note);
  })
  .get('/notes/:id', (ctx) => notes.get(ctx.url.params.id))
  .delete('/notes/:id', async (ctx) => {
    await notes.del(ctx.url.params.id);
    return 204;
  });
```

Every store call is async, so `await` them.

## 2. Redis in production

Point the same `kv()` at Redis and nothing else changes:

```js
import { kv } from '@server/next';
import { createClient } from 'redis';

const notes = kv(createClient({ url: process.env.REDIS_URL }));
```

## 3. One Redis for the whole app

Prefixes carve one backend into independent stores, so your data and the [auth](/documentation/authentication) users and logins can all share a single Redis:

```js
const redis = kv(createClient({ url: process.env.REDIS_URL }));
const notes = redis.prefix('note:');

export default server({
  auth: {
    strategy: 'cookie',
    providers: ['github'],
    users: redis.prefix('user:'),
    sessions: redis.prefix('session:'),
  },
});
// notes and the signed-in users now persist across restarts
```
