# Github login persisted in Redis

The same two callbacks as a SQL setup, against a key-value store instead. Useful when you have Redis already, or when you want the users to expire on their own.

## 1. The store

[polystore](https://polystore.dev/) turns a Redis client into one small interface. Install it alongside your client:

```bash
npm install polystore redis
```

```js
// db.js
import kv from 'polystore';
import { createClient } from 'redis';

const redis = kv(createClient({ url: process.env.REDIS_URL }));

export const users = redis.prefix('user:');
export const byEmail = redis.prefix('email:');
```

Prefixes carve one Redis into independent namespaces, so this can share an instance with the rest of your app.

## 2. The two callbacks

There are no secondary indexes, so the email lookup is a second key pointing at the id:

```js
import server from '@server/next';
import { users, byEmail } from './db.js';

const auth = {
  providers: 'github',

  onLogin: async (profile) => {
    const id = (await byEmail.get(profile.email)) ?? crypto.randomUUID();
    await byEmail.set(profile.email, id);
    await users.set(id, {
      id,
      email: profile.email,
      name: profile.name,
      avatar: profile.avatar,
      // Keep whatever is already stored, so a role survives the next login
      ...(await users.get(id)),
    });
    return id;
  },

  getUser: (id) => users.get(id),
};

export default server({ auth })
  .get('/me', (ctx) => ctx.user ?? 401);
```

`getUser` returns `null` for a missing key, which auth treats the same as `undefined`: that credential is signed out.

## 3. Expiring people

A raw store keeps values forever. Give the records a lifetime and inactive accounts clean themselves up, since every login rewrites the key:

```js
export const users = redis.prefix('user:').expires('90d');
```

Be deliberate about this one: it deletes accounts, not sessions. If a role or a plan lives on that record, losing it silently is worse than the disk it saves.

## 4. Roles

Same as anywhere else, since `ctx.user` is whatever you stored:

```js
  .get('/admin', (ctx) => {
    if (!ctx.user) return 401;
    if (ctx.user.role !== 'admin') return 403;
    return 'welcome';
  })
```

Setting one is a plain write: `await users.set(id, { ...user, role: 'admin' })`.
