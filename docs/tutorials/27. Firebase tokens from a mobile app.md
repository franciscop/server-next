# Firebase tokens from a mobile app

Firebase Authentication owns your user base: people sign in through its SDK with Google, Apple, a phone number or a password, and it issues an ID token. Your server verifies that token and nothing else.

## 1. Verify the token

```js
import server from '@server/next';

export default server({ auth: 'jwt:firebase' })
  .get('/api/me', (ctx) => ctx.user ?? 401);
```

```sh
FIREBASE_ISSUER=https://securetoken.google.com/my-project-id
FIREBASE_AUDIENCE=my-project-id
```

The project id appears in **both**: the issuer is per-project, and Firebase puts the same id in `aud`. The signing keys are Google's, and discovery finds them, so there is nothing else to configure.

Google Cloud Identity Platform is the same service under its enterprise name; `jwt:gcip` reads `GCIP_ISSUER` and `GCIP_AUDIENCE`.

## 2. Send it from the app

```swift
// iOS
let token = try await Auth.auth().currentUser?.getIDToken()
request.setValue("Bearer \(token!)", forHTTPHeaderField: "Authorization")
```

```js
// Web or React Native
const token = await auth.currentUser.getIdToken();
fetch('/api/me', { headers: { authorization: `Bearer ${token}` } });
```

Firebase ID tokens last an hour and the SDK refreshes them, so read the token before each call rather than caching it yourself.

## 3. What is in the claims

Without `getUser`, `ctx.user` is the token payload:

```js
{
  sub: 'kV9...',              // the Firebase uid, your foreign key
  email: 'ada@x.com',
  email_verified: true,
  name: 'Ada',
  picture: 'https://...',
  firebase: { sign_in_provider: 'google.com' },
}
```

`sub` is a **Firebase uid**, not a Google account id, even when someone signed in with Google. Firebase owns the account; Google was one way into it. `firebase.sign_in_provider` records which.

## 4. Map to your own table

```js
const auth = {
  verify: process.env.FIREBASE_ISSUER,
  audience: process.env.FIREBASE_AUDIENCE,
  getUser: (id) => db.users.byFirebaseUid(id),
};
```

Key your table on the uid. It is stable across sign-in methods, which the email is not.

## 5. Anonymous users

Firebase can issue tokens for anonymous accounts, which verify exactly like any other. If that matters, check the claim before treating someone as a real user:

```js
  .post('/orders', (ctx) => {
    if (!ctx.user) return 401;
    if (ctx.user.firebase?.sign_in_provider === 'anonymous') return 403;
    return db.orders.create(ctx.body);
  })
```
