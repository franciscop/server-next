# Github scopes and the access token

Signing in tells you who someone is. Asking for a **scope** also gets you permission to act for them, and the access token is that permission. This stores it and calls the GitHub API with it.

## 1. Ask for the scope

```js
import server from '@server/next';

const auth = {
  providers: { github: { scope: ['repo', 'read:user'] } },
  onLogin, getUser,
};
```

Scopes are per provider, because they only mean something to that provider. Ask for the narrowest set that works: people see them on the consent screen and a broad list costs you signups.

## 2. Store the token

It arrives on the profile, once, at login. Nothing keeps it for you:

```js
const onLogin = async (profile) => {
  const user = await db.users.upsert({ email: profile.email, name: profile.name });
  await db.tokens.set(user.id, encrypt(profile.accessToken));
  return user.id;
};
```

Encrypt it at rest. It is a live credential for someone else's account, and a leaked database row is a leaked GitHub account. Some providers also send `profile.refreshToken`, which you store the same way.

**Do not put it on `ctx.user`.** Under the `cookie` and `jwt` strategies whatever `ctx.user` holds is signed into the credential and readable by the client, so a token there ships to the browser on every request. Keep it in your own table and read it only where you need it.

## 3. Call the API

```js
  .get('/repos', async (ctx) => {
    if (!ctx.user) return 401;
    const token = decrypt(await db.tokens.get(ctx.user.id));
    if (!token) return 403;

    return fetch('https://api.github.com/user/repos', {
      headers: {
        authorization: `Bearer ${token}`,
        accept: 'application/vnd.github+json',
      },
    });
  })
```

Returning the `fetch` promise streams the response straight through.

## 4. Scopes people actually granted

Someone can approve less than you asked for. The granted set comes back with the token:

```js
const onLogin = async (profile) => {
  const id = (await db.users.upsert({ email: profile.email })).id;
  await db.tokens.set(id, {
    token: encrypt(profile.accessToken),
    scopes: profile.scopes ?? [],
  });
  return id;
};
```

Check it before offering a feature, rather than letting the API call fail with a `403` the person cannot act on.

## 5. Provider-specific fields

Anything outside the normalised profile arrives in `profile.raw`, untouched:

```js
  onLogin: (profile) => {
    const company = profile.raw.company;      // GitHub's own field
    const plan = profile.raw.plan?.name;
    // ...
  },
```
