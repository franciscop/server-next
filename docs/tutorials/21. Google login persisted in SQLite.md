# Google login persisted in SQLite

Two callbacks turn a cookie-only login into your own users table, with a role column and everything else. This uses SQLite through Bun; Postgres or MySQL is the same shape.

## 1. The table

```js
// db.js
import { Database } from 'bun:sqlite';

export const db = new Database('./data.db');

db.run(`CREATE TABLE IF NOT EXISTS users (
  id TEXT PRIMARY KEY,
  email TEXT NOT NULL UNIQUE,
  name TEXT,
  avatar TEXT,
  role TEXT NOT NULL DEFAULT 'member'
)`);
```

## 2. The two callbacks

`onLogin` runs once, after someone signs in, and returns **the id the cookie will point at**. `getUser` turns that id back into the person on every request:

```js
import server from '@server/next';
import { db } from './db.js';

const auth = {
  providers: 'google',

  onLogin: (profile) => {
    db.run(
      `INSERT INTO users (id, email, name, avatar)
       VALUES (?1, ?2, ?3, ?4)
       ON CONFLICT(email) DO UPDATE SET name = ?3, avatar = ?4`,
      [crypto.randomUUID(), profile.email, profile.name, profile.avatar],
    );
    return db.query('SELECT id FROM users WHERE email = ?').get(profile.email).id;
  },

  getUser: (id) => db.query('SELECT * FROM users WHERE id = ?').get(id),
};

export default server({ auth })
  .get('/me', (ctx) => ctx.user ?? 401);
```

```sh
SECRETS=a-long-random-string
GOOGLE_ID=...
GOOGLE_SECRET=...
```

Auth never sees the database: those two functions are the only contact. `ctx.user` is now your row, exactly as `SELECT *` returned it.

## 3. Two details in that upsert

**It matches on `email`, not the Google id.** Someone who later signs in another way keeps the same account.

**`ON CONFLICT` leaves `role` alone.** Promote someone in your admin panel and their next login will not quietly demote them.

## 4. Use the column

```js
  .get('/admin', (ctx) => {
    if (!ctx.user) return 401;
    if (ctx.user.role !== 'admin') return 403;
    return db.query('SELECT id, email, role FROM users').all();
  })
```

`getUser` runs per request, so a role change applies on the next one, and returning `undefined` from it signs that person out everywhere at once.

## 5. Refuse a login

Throw from `onLogin` and nobody gets in. The message reaches your error page as `?error=`:

```js
  onLogin: (profile) => {
    if (!profile.email.endsWith('@company.com')) {
      throw new Error('Use your work account');
    }
    // ...the upsert
  },
```
